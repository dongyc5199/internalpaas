# 服务器详情页集成方案

## 目标
- 将当前 Demo 版服务器详情页（含左侧导航和各信息分区）嵌入现有平台的 `main-layout` 和 `server-group-content` 体系。
- 保持平台统一的样式与脚本规范，同时支持后续接入真实数据和权限控制。

## 集成步骤

### 1. 准备工作
- 将 `demo-server-detail.html` 中的核心结构迁移为 Thymeleaf 片段或前端组件，命名建议为 `server-detail-content`。
- 确认页面引用的 Chart.js 已在平台全局资源中加载，避免重复引入。
- 设计稿中的色值和阴影已与平台主题兼容，无需额外设计变量。

### 2. 布局嵌入
- 在 `main-layout.html` 的 SPA 容器或对应路由下，通过 `th:replace` 引入新的详情片段。
- 保留 `page-shell` 容器以形成左右布局：左侧 `section-nav`，右侧 `.page-content`。
- 若从服务器列表弹层打开详情，需确保弹层容器允许左侧导航贴靠左边且支持 `position: sticky`。

### 3. 锚点与导航
- 详情内容区块需保持以下 ID：
  - `#server-overview` → 服务器概览
  - `#realtime-monitor` → 实时资源监控
  - `#process-info` → 进程信息
  - `#app-deployments` → 部署的应用
  - `#user-access` → 授权用户列表
- 左侧导航菜单链接指向上述 ID，并保留 `.section-nav`、`.is-active` 等类以复用样式。
- 将导航联动脚本（`IntersectionObserver` + 点击事件）封装为独立模块，初始化时传入容器节点，路由销毁时调用 `disconnect()`。

### 4. 数据与交互
- 详情内容中的静态数据需替换为真实接口返回值，可通过：
  - 在后端 Thymeleaf 渲染阶段注入模型，或
  - 在前端拉取 API 后更新 DOM/框架状态。
- 导航展示的当前服务器名、状态标签、按钮行为（返回列表/SSH）应与平台现有逻辑一致。
- 保留“暂停刷新”“收起图表”等按钮的事件挂载，与监控数据轮询逻辑共享状态。

### 5. 资源与样式
- 将新增样式合并至平台的模块化样式文件（如 `server-group-management.css`），避免散落在模板内。
- 确保 `scroll-behavior: smooth` 设置不会与平台其他滚动动画冲突，必要时仅对详情容器生效。
- 若平台存在暗色主题，需检查导航渐变与阴影在暗色模式下的表现，可借助 CSS 变量调整透明度。

### 6. 测试与验证
- 桌面端：验证导航点击与滚动高亮、图表刷新、弹层关闭等行为。
- 移动端（≤1100px）：确认导航转为横向排布且易于点击。
- 可访问性：检查键盘导航在菜单和内容区之间切换时的焦点样式与跳转逻辑。
- 性能：在 SPA 路由切换时销毁定时器与观察者，防止内存泄露。

## 后续优化建议
- 将导航与图表刷新逻辑抽象为可复用的 Hook/Service，便于其他详情页复用。
- 接入实时数据时优先支持 WebSocket/SSE，并在“暂停刷新”按钮中打通实时订阅的挂断与恢复。
- 与权限系统对接，按用户角色决定部分操作按钮（如“打开 SSH”“终止进程”）是否展示。
