## 背景与目标

### 背景
- 当前平台已实现 **管理员角色** 的核心能力（服务器群组管理、用户管理等）。
- 开发者账号由管理员创建并分配，开发者对基础设施的权限应受控且可审计。
- 平台计划扩展到**应用服务**层面的运维协同，让开发者能够在统一的工作台中管理自身负责的服务。

### 业务目标
1. 允许开发者使用管理员分配的账号登录平台，完成身份鉴别与授权。
2. 为开发者提供与管理员一致的工作台基础视觉风格，降低学习成本。
3. 提供**应用服务管理**菜单，覆盖开发者工作主流程：查看、调整、交付应用服务。
4. 在权限受限的前提下，提高开发团队对应用级资源的自助管理能力，减少管理员操作负担。
5. 保障应用制品仅从开发者获准的工作目录上传，结合在线配置编辑、服务生命周期控制、受控 SSH 终端排障与日志分析，实现端到端交付闭环。

### 范围
- 本次需求仅针对“开发者”系统角色。
- 管理员已有能力保持不变，如需委派或审批流程将在后续版本规划。
- “应用服务管理”模块的配置、部署、监控属于当前需求范围。

### 不在范围
- 自动化部署流水线的高级编排（例如灰度、滚动升级策略）。
- 第三方 CI/CD 平台集成。
- 跨角色消息通知中心（先保持现有机制）。

## 角色定义与权限边界

| 角色 | 登录入口 | 可访问模块 | 操作权限 | 备注 |
|------|----------|------------|----------|------|
| 管理员 | `/login` | 服务器群组管理、用户管理、应用服务管理（全部）、系统设置等 | 全量 CRUD、审批、权限分配 | 现有实现 |
| 开发者 | `/login` | 应用服务管理（受限）、个人设置（计划中的共性模块） | 对授权应用服务的受限操作 | 新增 |

### 开发者角色权限原则
1. **最小权限**：仅能查看与操作自己被授权的应用服务及相关部署历史。
2. **只读默认**：除部署、重启等经过授权的操作外，其余敏感操作（删除、编辑全局配置）默认只读。
3. **可追踪**：所有开发者操作必须记录到审计日志，供管理员回溯。
4. **资源隔离**：开发者之间不可互相查看未授权的应用服务。

## 业务场景与用户旅程

### 关键角色
- **开发者 (Primary Actor)**：负责日常应用服务的配置、上线与回滚。
- **管理员 (Supporting Actor)**：创建开发者账号、配置应用服务授权边界。

### 核心用户旅程

1. **账号分发**
   - 管理员在“用户管理”中创建开发者账号，分配初始密码和授权的应用服务列表。
   - 开发者首次登录后被引导修改密码。

2. **日常管理**
   - 登录后进入主工作台，左侧菜单仅显示“应用服务管理”。
   - 进入列表页查看自己有权限的应用服务，支持多维度过滤（环境、部署状态、标签等）。
   - 选择某个服务进入详情页，查看部署拓扑、版本信息、运行状态。

3. **部署操作**
   - 在详情页发起部署：从授权工作目录或制品仓库选择制品版本、填写变更说明、触发部署流程。
   - 实时查看部署日志和进度；部署完成后可回滚至上一稳定版本。

4. **运行维护**
   - 查看应用运行指标与告警摘要（需与监控模块对接）。
   - 通过生命周期面板执行启动、优雅重启、强制停止、扩缩容等操作，实时查看反馈。
   - 记录操作原因并生成审计日志。

5. **配置与日志协同**
   - 在 Web 界面查看、编辑配置文件，提交前进行语法校验及差异审阅，并触发审批。
   - 通过日志分析面板定位异常、关联部署或配置变更，必要时导出报表。
6. **远程排障（SSH 终端）**
   - 在受控的 Web SSH 终端中连接至目标服务器，仅允许访问自身工作目录及其子目录。
   - 支持常用文件操作（查看、编辑、上传下载）和诊断命令，采用指令白名单/黑名单组合限制高危命令。
   - 终端会话全程审计，提供实时命令回显与自动超时断开，异常操作触发告警。
7. **历史追踪**
   - 在“变更记录”中查看自身操作的时间线、结果状态、审计详情。

## 功能需求拆解

### F1. 登录与身份管理
- 支持开发者使用管理员分配的账号登录 `/login`。
- 登录成功后根据角色进入相同风格的工作台首页，但可访问菜单不同。
- 首次登录需强制修改密码（依赖现有安全策略）。
- 支持账号锁定、密码重置等运维操作（沿用管理员配置）。

### F2. 工作台与导航
- 顶部导航、版式、主题与管理员一致，保持统一品牌体验。
- 左侧菜单：仅显示 `应用服务管理` 主菜单，默认展开。
- 后续可扩展次级菜单：`服务列表`、`部署历史`、`常用模板`（预留二级结构）。

### F3. 应用服务列表
- 仅展示开发者被授权的应用服务。
- 列表字段（建议）：服务名称、环境、当前版本、最近部署人/时间、运行状态、所在集群。
- 支持搜索、排序、筛选（环境、标签、运行状态）。
- 行操作包括：查看详情、快速部署（快捷入口）、快速重启（需授权）。
- 应用制品上传入口仅接受当前用户工作目录或管理员指定的制品仓库资源，禁止跨用户路径或未知主机访问。

### F4. 应用服务详情
- **概览页**：服务基础信息、负责小组、关联服务器群组、关联告警、负责人联系方式。
- **工作目录制品管理**：
  - 明确显示当前服务对应的工作目录及默认制品存储路径。
  - 支持在工作目录中挑选制品（压缩包、镜像描述文件等），或引用管理员批准的制品仓库。
  - 对不同环境可配置独立的制品来源白名单。
- **部署管理**：
  - 查看部署历史（版本、状态、耗时、触发人、备注）。
  - 发起部署：选择目标环境、制品版本、部署策略（标准/快速）、部署说明，默认仅允许上传位于用户工作目录下的制品。
  - 部署过程中展示实时日志与阶段进度条，可随时终止（根据权限）。
  - 部署后自动校验制品留存路径与工作目录一致性。
- **服务生命周期控制**：
  - 集成启动、优雅重启、强制停止等常见操作，提供操作前确认和状态反馈。
  - 支持按实例、按服务级别执行，需结合权限模型限制批量操作频次。
  - 提供自动健康检查或回滚建议。
- **配置文件管理**：
  - 支持在线查看、编辑、对比差异（版本快照）与回滚。
  - 编辑界面提供语法高亮、模板校验及变更说明记录。
  - 保存时触发配置生效流程（如热加载或提示重启）。
- **运行维护**：
  - 查看当前实例列表（实例ID、节点、状态、CPU/内存快照）。
  - 支持批量操作（重启、下线、上线）——需配额控制。
  - 操作需二次确认，并写入审计日志。
- **日志分析**：
  - 集成实时日志流与历史日志查询，支持关键字搜索、追踪ID过滤、错误聚类。
  - 可将日志切片关联至部署记录或告警事件，并支持导出。
- **监控集成**（可选/后续接入）：
  - 显示核心指标（QPS、错误率、响应时间），支持跳转至监控平台。
  - 维持账号权限传递，确保开发者仅访问授权监控数据。

### F5. 审计与通知
- 所有关键操作（部署、回滚、重启、扩缩容）自动记录：
  - 记录内容：操作人、操作对象、动作、时间、结果、原因备注。
  - 审计数据需支持管理员查询导出。
- 部署结果自动向相关负责人（开发者 + 管理员）发送通知（邮件/站内信，沿用现有渠道）。

### F6. 权限与资源管理（后台能力）
- 管理员在用户管理中可为开发者分配应用服务权限（单个、批量、按标签）。
- 支持读取权限模板（例如“服务负责人”“只读观察者”）。
- 需提供权限校验接口，供前后端调用以判断操作是否允许。

### F7. SSH 终端操作
- 在 Web 页面提供与管理员一致的 SSH 终端组件，但默认载入开发者自身的工作目录作为根路径。
- 终端仅允许执行白名单内的命令（如 `ls`、`cat`、`tail`、`vim`、`kubectl get` 等运维低危指令），对高危命令（`rm -rf /`、`sudo`、`reboot`、`systemctl` 等）实行黑名单拦截。
- 禁止切换到系统关键目录（`/etc`、`/var/lib` 等），所有 `cd` 操作需通过路径校验确保仍位于工作目录内。
- 提供多标签会话、键入历史与上传/下载（SFTP）能力，但文件传输同样仅限工作目录。
- 支持快捷插入常用诊断脚本模板，并在界面上提示操作风险与最佳实践。
- 终端会话需记录命令、输出、时间、目标服务器、IP 等信息，供审计查询与回放。

## 交互与界面要求

1. **视觉风格一致性**
   - 继承管理员工作台的配色、组件风格、布局。
   - 顶部展示角色标识（如头像旁标签 “Developer”），以便用户确认当前身份。

2. **信息架构**
   - `应用服务管理` 下第一层展示服务列表；详情页使用标签页布局（概览 / 部署 / 版本 / 运行 / 审计）。
   - 部署流程采用 3~4 步向导（选择版本 → 配置策略 → 确认 → 实时状态）。

3. **反馈机制**
   - 关键操作需二次确认对话框，并显示预计影响。
   - 成功 / 失败采用通知条 + 活动日志双重反馈。

4. **空状态与异常处理**
   - 若开发者未被授权任何服务，展示引导/联系管理员的空状态页。
   - 接口异常时保持页面可读性，提供重试入口。

## 数据模型与接口需求

### 主要实体
- `DeveloperUser`: 开发者账号信息、所属团队、状态。
- `ApplicationService`: 服务基本信息、环境标签、关联资源 ID。
- `ServicePermission`: 用户与服务之间的授权关系（权限级别：读/部署/维护）。
- `DeploymentRecord`: 部署历史，包含制品版本、流水线 ID、结果、耗时。
- `ServiceInstance`: 运行实例，包含节点、状态、健康度。
- `WorkspaceArtifact`: 与用户工作目录关联的制品元数据（路径、哈希、可见性）。
- `ServiceConfigFile`: 配置文件快照、版本、变更说明、回滚指针。
- `LogEvent`: 日志条目或聚合结果，包含来源实例、级别、traceId 等扩展信息。
- `TerminalSession`: SSH 会话记录，包含开始/结束时间、目标服务器、会话状态、触发来源。
- `TerminalCommandAudit`: 终端命令审计条目，记录命令、执行结果、退出码、命中策略（白名单/黑名单）。
- `AuditLog`: 审计记录。

### 接口需求概览

| 接口 | 方法 | 描述 |
|------|------|------|
| `/api/auth/login` | POST | 登录，沿用现有接口，需返回角色信息 |
| `/api/services` | GET | 获取授权服务列表，支持过滤条件 |
| `/api/services/{id}` | GET | 获取服务详情（含基本信息、权限、监控摘要、工作目录信息） |
| `/api/services/{id}/artifacts` | GET | 列出工作目录内可用制品，返回路径、哈希、更新时间 |
| `/api/services/{id}/artifacts/upload` | POST | 上传工作目录制品（校验白名单），支持断点续传/秒传 |
| `/api/services/{id}/deployments` | GET | 获取部署历史 |
| `/api/services/{id}/deploy` | POST | 触发部署，参数包含制品版本、策略、说明 |
| `/api/deployments/{id}/logs` | GET | 获取部署实时日志 |
| `/api/services/{id}/lifecycle` | POST | 执行启动/停止/重启等操作，需传入动作类型与目标范围 |
| `/api/services/{id}/rollback` | POST | 回滚至指定版本 |
| `/api/services/{id}/config-files` | GET | 获取配置文件目录树与最新版本摘要 |
| `/api/services/{id}/config-files/{fileId}` | PUT | 提交配置修改，附带变更说明、审批信息、回滚标记 |
| `/api/services/{id}/config-files/{fileId}/diff` | GET | 查看配置文件版本差异 |
| `/api/services/{id}/logs/stream` | GET (WebSocket) | 订阅实时日志流，可按实例、级别过滤 |
| `/api/services/{id}/logs/query` | POST | 检索历史日志，支持时间范围、关键字、traceId |
| `/api/services/{id}/terminal/session` | POST | 建立受控 SSH 终端会话，初始化工作目录并返回会话 token |
| `/api/services/{id}/terminal/session/{sessionId}` | DELETE | 主动关闭 SSH 会话或因违规操作强制断开 |
| `/api/services/{id}/terminal/command` | POST | 发送终端命令，包含白名单校验与路径审查 |
| `/api/services/{id}/terminal/stream` | GET (WebSocket) | 监听终端输出、命令审计事件及安全告警 |
| `/api/services/{id}/instances` | GET | 获取运行实例列表 |
| `/api/services/{id}/instances/actions` | POST | 执行实例操作（重启/上下线等），需权限验证 |
| `/api/audit` | GET | 查询开发者操作审计记录（管理员使用） |

> 注：若部分接口已存在于管理员使用的模块，则需增加角色判断与数据过滤。

## 安全与合规要求

1. **访问控制**：后端基于角色与服务授权双重校验，前端隐藏未授权按钮。
2. **工作目录隔离**：制品上传、文件浏览必须校验工作目录白名单，禁止路径穿越及符号链接攻击。
3. **终端指令策略**：SSH 终端需执行命令白名单/黑名单校验，自动阻断高危指令并支持动态策略下发。
4. **配置修改审计**：配置文件编辑需记录差异、审批人、变更说明，可选启用双人复核。
5. **服务操作防护**：部署、回滚、启动/停止等高风险操作需 OTP/二次验证（可配置）并限定频率。
6. **密码策略**：沿用平台统一策略（复杂度、过期提醒、锁定阈值）。
7. **审计合规**：操作日志需保留 ≥ 180 天，可导出 CSV/PDF。
8. **日志访问控制**：日志分析接口需按服务与环境双重校验并对敏感字段脱敏。
9. **数据保护**：部署凭证、制品密钥等敏感信息由服务端托管，不在前端暴露。

## 性能与可用性要求

| 指标 | 目标值 |
|------|--------|
| 服务列表加载时间 | ≤ 2 秒（授权服务 ≤ 200 个） |
| 部署详情实时刷新 | 2 秒/次，允许 WebSocket 或长轮询 |
| 部署触发 API 响应 | ≤ 1 秒（异步执行，返回任务 ID） |
| 服务生命周期指令响应 | ≤ 2 秒返回执行受理状态 |
| 配置差异渲染 | ≤ 1 秒展示 <1 MB 文件的 diff |
| 日志查询 | ≤ 5 秒返回最近 15 分钟内的聚合结果 |
| SSH 命令往返延迟 | ≤ 500 ms（不含网络 RTT），超时自动重试 |
| 并发终端会话数 | 单用户 ≤ 3，会话超时 10 分钟无操作自动断开 |
| 审计日志写入 | 同步写入成功率 100%，失败需告警 |
| 可用性 | ≥ 99.5%（依赖平台整体 SLA） |

## 验收标准

### 功能验收
- [ ] 开发者能够使用管理员分配的账号登录并看到限定菜单。
- [ ] 未授权的服务不会出现在应用服务列表中。
- [ ] 详情页可展示完整的服务信息、部署历史、运行实例。
- [ ] 开发者可以在授权范围内部署、回滚、重启实例，并产生审计记录。
- [ ] 部署过程提供实时日志，操作结果通知开发者与管理员。
- [ ] 应用制品上传仅接受工作目录或授权仓库资源，越界时阻断并告警。
- [ ] 配置文件可在线编辑、预览差异并保留版本记录。
- [ ] 服务启动、停止、重启等生命周期操作具备执行反馈与审计记录。
- [ ] 日志分析页面支持实时流与历史检索，权限隔离准确。
- [ ] 开发者可在受控 SSH 终端内操作自身工作目录，命令拦截与会话审计生效。

### 安全验收
- [ ] 登录后 API 返回的角色信息正确，权限校验覆盖所有关键接口。
- [ ] 审计日志完整记录关键操作，管理员可查询导出。
- [ ] 部署/回滚等操作具备二次确认机制。

## 风险与待确认事项

| 风险/问题 | 描述 | 影响 | 建议处理 |
|-----------|------|------|----------|
| 应用服务数据来源 | 是否已有统一的应用配置中心或制品库 | 高 | 明确数据接口或准备 Mock 数据 |
| 工作目录一致性 | 目标服务器是否预置统一的工作目录结构及权限 | 高 | 梳理目录挂载与授权策略，提供创建前自检脚本 |
| 权限粒度 | 目前是否支持到“服务+环境”级别的授权 | 中 | 确认是否需要多维授权模型 |
| 部署实现方式 | 平台自身是否具备部署引擎，或需对接外部流水线 | 高 | 明确技术选型，决定接口定义 |
| 配置热加载能力 | 目标服务是否支持在线热更新或需重启 | 中 | 与服务团队确认加载策略，必要时提供重启提示 |
| 监控/日志集成 | 是否已有统一监控平台 API | 中 | 如无，当前版本可提供跳转链接 |
| 安全合规 | 是否需满足特定审计、合规要求（例如通用规范） | 中 | 与安全团队确认保留周期与格式 |
| 日志数据量 | 实时日志与历史检索的体量及存储成本 | 中 | 制定日志留存策略，联动日志平台分级存储 |
| SSH 终端权限控制 | 白名单/黑名单策略维护成本与误杀风险 | 中 | 建立安全策略评审机制，提供动态配置与回放校验 |
| 角色扩展 | 未来是否会有更多子角色（如只读开发者） | 低 | 预留权限模板与角色扩展能力 |

**下一步建议**
1. 与管理员角色的业务方确认应用服务管理的权限细化方案。  
2. 梳理现有系统中关于应用服务、部署、监控的接口资产。  
3. 准备前端原型稿（基于管理员风格），快速验证信息架构。  
4. 制定联调与验收计划，确保上线前覆盖关键路径测试。  
5. 对齐各环境的工作目录挂载与权限策略，补齐自动化脚本与巡检。  
6. 明确配置文件与日志平台的集成方式（API、鉴权、脱敏策略）。  
7. 制定 SSH 终端命令白名单/黑名单策略与更新流程，构建模拟环境验证误杀风险。
