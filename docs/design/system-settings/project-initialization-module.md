# 系统设置 - 项目信息初始化模块设计

**版本**: 0.1  
**日期**: 2025-10-27  
**作者**: AI Assistant  
**状态**: 设计草案（管理员功能）

---

## 1. 背景与目标

- 针对新项目落地阶段，提供一键式初始化能力，自动导入服务器信息与项目成员信息。  
- 入口位于 **系统设置** -> **项目信息配置**，仅管理员角色可见。  
- 初始化后，现有的“服务器群组管理”“人员管理”功能继续使用，不受影响。

---

## 2. 页面结构 & 交互

```
┌──────────────────────────── 系统设置 ▸ 项目信息配置 ────────────────────────────┐
│ 项目信息                                                                   │
│  ├─ 项目名称 [Input]                                                       │
│  ├─ 服务器清单 [文件上传] (CSV/XLSX)                                       │
│  ├─ 人员清单 [文件上传] (CSV/XLSX)                                         │
│  ├─ 配置说明/下载模板链接                                                  │
│  └─ [初始化项目] 按钮 (需要二次确认)                                      │
│                                                                            │
│ 初始化历史                                                                 │
│  └─ 列表显示最近操作（时间、操作人、导入结果、详情下载）                   │
└────────────────────────────────────────────────────────────────────────────┘
```

- 上传区显示文件名称、大小、校验结果（格式错误/内容校验）。  
- “初始化项目”按钮需弹出确认框，提示将覆盖现有记录（可选：只添加不存在的条目）。  
- 初始化成功后，展示结果摘要：新增服务器数、人员数、异常行数等。  
- 历史记录可下载导入日志（CSV/JSON）用于审计。

## 3. 文件格式

### 3.1 服务器清单（CSV/XLSX）

| 字段 | 说明 | 示例 |
|------|------|------|
| `hostname` | 主机名 | `app-node-01` |
| `ip` | IP 地址 | `10.10.1.20` |
| `env` | 环境标识 | `DEV` / `PROD` |
| `role` | 服务器角色/标签 | `web`, `db`, `cache` |
| `os` | 操作系统 | `CentOS 7.9` |
| `cluster` | 归属集群/机房 | `IDC-A` |
| `remarks` | 备注 | 可为空 |

- 校验要求：IP 合法性、环境字段必须在预设列表内。  
- 导入后写入服务器基础表，并与服务器群组功能共享数据源。

### 3.2 人员清单（CSV/XLSX）

| 字段 | 说明 | 示例 |
|------|------|------|
| `username` | 登录账号 | `wangran` |
| `fullName` | 姓名 | `王然` |
| `email` | 邮箱 | `wangran@example.com` |
| `phone` | 联系电话 | `13800138000` |
| `role` | 角色类型 | `开发者` / `管理员` / `运维` |
| `team` | 所属团队 | `DevOps` |
| `enable` | 是否启用 | `true/false` |

- 角色字段需映射到平台角色表；不存在的角色需提示或由管理员选择映射。  
- 可选创建初始密码（随机生成后通知管理员）。

## 4. 后端流程

1. **上传文件**  
   - 保存至临时存储（`/tmp/project-init/{sessionId}`），立刻解析验证。  
   - 若校验失败，显示错误明细（行号、原因），禁止继续。

2. **初始化项目**  
   - 记录操作员、时间、文件指纹。  
   - 开启事务/批处理：
     1. 若项目名称在系统不存在，则创建新项目记录。  
     2. 批量写入服务器表 `server_info`，自动创建默认服务器群组（按 env/role 分组可选）。  
     3. 批量写入人员表 `user_account`，设置角色关系。  
     4. 生成对应的审计日志和历史记录。  
   - 如有重复：可配置“忽略/更新/报错”策略（默认忽略已存在的记录）。

3. **通知与审计**  
   - 初始化结果写入 `project_init_history`：新增数量、失败数量、失败明细文件路径。  
   - 若需要审批或通知，调用内部消息中心发送结果摘要。

---

## 5. 数据库设计建议

| 表名 | 说明 |
|------|------|
| `project_info` | 项目基础信息（名称、描述、创建人、创建时间）。 |
| `project_init_history` | 初始化记录（项目、操作人、状态、服务器数、人员数、详情 JSON）。 |
| `project_init_error_log` | 可选，存储失败行明细。 |
| `server_info` / `user_account` | 复用现有表，增加 `project_id` 字段（可选，用于隔离）。 |

---

## 6. 接口草案

| 接口 | 方法 | 描述 |
|------|------|------|
| `/admin/settings/project-config/content` | GET | 页面 fragment |
| `/admin/settings/project-config/upload/server` | POST | 上传服务器清单（返回解析结果） |
| `/admin/settings/project-config/upload/member` | POST | 上传人员清单 |
| `/admin/settings/project-config/init` | POST | 初始化项目（请求体包含项目名称、两份文件指针、策略） |
| `/admin/settings/project-config/history` | GET | 初始化历史列表 |
| `/admin/settings/project-config/history/{id}` | GET | 详情/下载导入报告 |

---

## 7. 权限与安全

- 仅 `ROLE_ADMIN` 拥有访问/操作权。  
- 文件上传大小限制（默认 < 10MB），同时强制使用 HTTPS/内网安全网关。  
- 执行初始化前进行二次确认（提示覆盖范围、导入数量）。  
- 操作需写入审计日志并保留导入文件（加密存储）。

---

## 8. 辅助功能

- 提供模板下载按钮（CSV/XLSX 模板）。  
- 支持先进行“演练”模式：只校验不写入（Dry Run），便于检查文件。  
- 导入成功后可跳转到服务器群组或人员管理页面查看结果。  
- 支持再次导入时选择“仅新增”或“同步更新”模式。

---

## 9. 开放问题

1. 是否需要支持多项目并存？若是，需在服务器/人员表加 `project_id` 字段。  
2. 人员角色如何与现有 RBAC 绑定（是否允许创建新角色）。  
3. 需要与外部系统对接吗（如已有 CMDB、人事系统）。  
4. 导入后的自动化脚本（如自动初始化服务器监控 agent）是否需要集成。  
5. 审批流程是否必选，还是允许直接执行。
