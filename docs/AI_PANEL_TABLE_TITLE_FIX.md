## 🔴 问题描述

当 AI 输出带标题的表格时，标题行被错误地解析为表格的第一列，导致：

### 错误渲染效果

```
| 猫与狗的性格对比（简明表格） | 相性 |
|------------------------------|------|
| 猫 (Feliscatus)              | ...  |
| 狗 (Canislupusfamiliaris)    | ...  |
```

❌ 标题 "猫与狗的性格对比（简明表格）" 被当成了第一列
❌ "相性" 被当成了第二列
❌ 实际的列数据错位

### 期望渲染效果

```
猫与狗的性格对比（简明表格）
┌────────┬──────────────┬────────────────────────┐
│  相性  │ 猫 (Feliscatus) │ 狗 (Canislupusfamiliaris) │
├────────┼──────────────┼────────────────────────┤
│ 社交取向 │ 独居偏冷，选性社交 │ 群居驱动，渴望依附人类 │
└────────┴──────────────┴────────────────────────┘
```

✅ 标题独立显示在表格上方
✅ 表头正确显示为 "相性", "猫", "狗"
✅ 数据行正确对齐

## 🔍 问题根因分析

### Markdown 表格标准格式

标准 Markdown 表格格式要求：

```markdown
| 列1 | 列2 | 列3 |
|-----|-----|-----|
| 数据1 | 数据2 | 数据3 |
```

- **第1行**：表头
- **第2行**：分隔符（必需）
- **第3+行**：数据行

### AI 输出的实际格式

但 AI 经常输出带标题的表格：

```markdown
表格标题文字
| 列1 | 列2 | 列3 |
|-----|-----|-----|
| 数据1 | 数据2 | 数据3 |
```

- **第1行**：表格标题（不含管道符或管道符很少）
- **第2行**：真正的表头
- **第3行**：分隔符
- **第4+行**：数据行

### 原有解析逻辑的问题

在 `ai-panel.js` 的 `parseTable` 函数中（737行）：

```javascript
function parseTable(i){
    const header = lines[i];      // ❌ 直接将第 i 行当作表头
    const sep = lines[i+1]||'';   // ❌ 将第 i+1 行当作分隔符

    // 验证分隔符
    if (!/^\s*\|?\s*(:?-+:?\s*\|)+\s*:?-+:?\s*\|?\s*$/.test(sep)) return 0;
    // ...
}
```

当第一行是标题文字时：
- `header` = "猫与狗的性格对比（简明表格）"
- `sep` = "| 相性 | 猫 (Feliscatus) | 狗 (Canislupusfamiliaris) |"
- ❌ 分隔符验证失败，导致表格无法正确解析

## ✅ 修复方案

### 1. 智能识别表格标题

在 `parseTable` 函数中添加标题行检测逻辑：

```javascript
function parseTable(i){
    const header = lines[i]; const sep = lines[i+1]||'';
    if (!header || header.indexOf('|')===-1) return 0;

    // 🆕 检查是否有标题行（非管道符开头的文本）
    let titleLine = null;
    let headerLine = header;
    let sepLine = sep;
    let startRow = i;

    // 🆕 如果第一行不包含管道符或管道符很少，可能是表格标题
    const pipeCount = (header.match(/\|/g) || []).length;
    if (pipeCount <= 1 && lines[i+1] && lines[i+1].indexOf('|') > -1) {
      // 第一行是标题，第二行是表头
      titleLine = header.trim();
      headerLine = lines[i+1];
      sepLine = lines[i+2] || '';
      startRow = i + 1;
    }

    // 验证分隔符行
    if (!/^\s*\|?\s*(:?-+:?\s*\|)+\s*:?-+:?\s*\|?\s*$/.test(sepLine)) return 0;

    // ... 解析表格 ...

    // 🆕 如果有标题行，先输出标题

    }

}
```

## 📚 识别规则总结

表格标题自动识别规则：

```javascript
// 条件1：当前行管道符数量 ≤ 1
pipeCount <= 1

// 条件2：下一行包含管道符（是真正的表头）
lines[i+1].indexOf('|') > -1

// 满足以上两个条件 → 当前行是标题
```

**示例判断**：

| 输入文本 | 管道符数量 | 下一行有管道符 | 判断结果 |
|----------|-----------|--------------|---------|
| `系统配置` | 0 | ✅ | ✅ 标题 |
| `版本 \| 对比` | 1 | ✅ | ✅ 标题 |
| `\| 列1 \| 列2 \|` | 3 | ✅ | ❌ 表头 |
| `普通文本` | 0 | ❌ | ❌ 段落 |

## 🎓 经验教训

### 1. 处理真实世界的输入

❌ **不要假设输入严格遵循规范**
```markdown
# 理想格式（规范）
| 列1 | 列2 |
|-----|-----|
```

✅ **允许更自然的输入**
```markdown
# 真实格式（带标题）
表格标题
| 列1 | 列2 |
|-----|-----|
```

### 2. 渐进式增强

- 保持向后兼容（标准表格仍然正常工作）
- 添加新功能（自动识别标题）
- 不破坏现有功能

### 3. 视觉设计的重要性

好的解析逻辑 + 好的视觉设计 = 优秀的用户体验

- 标题区域有明显的视觉区分
- 颜色和间距传达层次关系
- 一致的设计语言（使用主题色）

## 📞 技术支持

如遇到表格渲染问题，请检查：

1. **表格格式** - 是否符合 Markdown 表格语法
2. **分隔符行** - 第二行或第三行是否为 `| --- | --- |`
3. **管道符对齐** - 每行的列数是否一致
4. **标题识别** - 标题行管道符数量是否 ≤ 1
