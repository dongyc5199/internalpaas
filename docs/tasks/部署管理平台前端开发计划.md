## 一、背景与目标
- 主应用已引入 React 微前端骨架，并在管理后台挂载 `deploy-platform` 子应用，完成 Token Bridge 与模块联邦入口的首轮打通。
- 当前仅具备静态骨架界面，缺乏真实数据对接、金丝雀监控、审批流、审计材料等业务能力。
- 目标是在 3 个迭代（约 6~8 周）内完成部署管理平台前端 MVP，覆盖核心发布、回滚、灰度监控、策略配置与审计功能，并与主应用管理员角色深度融合。
- 所有交付需符合「每个任务结束 → 代码自检 → Code Review → 单测/集成测试」的流程，直至主应用集成环境验证通过。

## 二、设计约束与集成要点
- **技术栈**：React 18 + TypeScript + Vite + Module Federation；状态层采用 React Query + Zustand；表单基于 React Hook Form + Zod。
- **鉴权模型**：微前端通过 `token-bridge` 获取 BFF 短期 JWT，所有 API 走主应用 BFF（`/api/deploy-platform/*`）。
- **UI 规范**：复用主应用 Design Token、排版与图标体系，样式使用 CSS Modules，禁止全局污染；支持中英文双语。
- **可观测性**：重要操作需暴露日志（console warn/error）、埋点（预留 `tracker.ts` 接口），并与后端审计字段一致。
- **CI/CD**：每次合并需跑通 `npm run lint && npm run test:run && npm run build`；Argo 将在后续流水线中集成自动化测试。
- **Argo 集成前提**：前端发布包需包含 `deploy-platform/bootstrap` 入口，保证 Host 侧 `remotes["deploy-platform"]` 能解析。

## 四、阶段任务拆分
### Sprint 1（M1范围：发布总览与审批流）
1. **T1 - 信息架构与路由搭建**
   - 设计 React Router 层级：`/overview`、`/releases/:id`、`/settings/policies` 等；
   - 落地导航侧栏、顶部操作区，与主应用样式对齐。
2. **T2 - 概览仪表盘（现骨架升级）**
   - 引入真实 API（`GET /api/deployments`），实现应用场景聚合卡片；
   - 补充加载、空态、错误态，封装 `useDeploymentSummary` Hook。
3. **T3 - 发布列表 & 详情**
   - 列表支持过滤（应用、环境、状态），详情页展示时间轴与守门指标；
   - 集成审批操作按钮（调用 `/api/releases/{id}/advance`）。
4. **T4 - 审批与通知**
   - 实现审批对话框、越权备注、操作确认；
   - 接入主应用消息中心（postMessage 通知 or Toast），与 Token 续期联动。
5. **T5 - 单元 & 集成测试**
   - 对 Hooks、组件、API Mock 编写 Vitest + Testing Library；
   - 编写 Playwright 场景：加载 → 查看列表 → 审批 → 校验状态。
6. **T6 - 回归与 Code Review**
   - 自查清单：UI、i18n、可访问性、性能；
   - 发起内部 CR，修复反馈后方可合并。

### Sprint 2（M2范围：灰度与策略）
1. **T7 - 金丝雀阶段看板**
   - 处理阶段转换动画、指标曲线展示（折线图组件封装）；
   - 引入 Prometheus API 接口（BFF 聚合）。
2. **T8 - 策略配置中心**
   - 实现策略列表、创建/编辑表单、验证提示（`POST /api/policies/validate`）；
   - 表单与 Zod 校验结合，支持 JSON Schema 可视化预览。
3. **T9 - Token 续期 & 异常处理**
   - 完成 token-bridge 续期提示 UI、错误兜底（自动刷新/弹窗）；
   - 与 Host `deploy-platform-auth` 脚本联调，记录失败审计。
4. **T10 - 灰度操作与回退**
   - 提供阶段控制（推进/暂停/回滚），与 Rollouts 状态对齐；
   - 增加守门失败提示与人工越权流程。
5. **T11 - 自动化测试矩阵**
   - 新增 Playwright 场景：金丝雀推进、策略校验失败、Token 过期；
   - 引入契约测试（MSW/vitest）模拟 BFF 响应。
6. **T12 - CR & 测试闭环**
   - 统一走 CR；更新测试报告、截图、指标；
   - 与后端、BFF 团队联调确认。

### Sprint 3（M3范围：审计、数据作业、降级）
1. **T13 - 审计材料包浏览**
   - 列表展示、过滤、下载入口（`GET /api/audits/{releaseId}`）；
   - 支持内嵌 PDF/Markdown 预览。
2. **T14 - 数据作业灰度面板**
   - 影子/采样执行状态、对比结果可视化；
   - 失败场景提示与回滚建议。
3. **T15 - 回滚向导**
   - Wizard 步骤：选择版本 → 策略校验 → 确认 → 监控；
   - 集成表单校验、审批流程复用。
4. **T16 - 离线/降级策略**
   - Host 页面提供“加载失败/Token 无法续期”降级提示；
   - 预留 iframe 退路与只读模式开关。
5. **T17 - 性能与可访问性优化**
   - 构建分析、代码分包、懒加载；
   - 针对关键组件进行 a11y 自测（ARIA、键盘导航）。
6. **T18 - 总体验收与文档更新**
   - 更新使用手册、Runbook、发布检查表；
   - 组织联调演示并收集反馈，拉齐后续 Backlog。

## 五、代码评审与测试要求
- **代码评审**：每个任务完成后必须发起 PR，自查通过 Checklist（功能、样式、i18n、日志、异常处理、测试覆盖）后请求至少一名负责人评审。
- **测试策略**：
  - 单元测试：组件、Hooks、工具函数覆盖率 ≥70%，关键逻辑 ≥90%。
  - 合同测试：Mock Service Worker / Pact 保证 BFF 契约稳定。
  - E2E 测试：Playwright 场景覆盖核心业务流；CI 中 nightly 运行。
  - 手工验收：通过 Admin 模式进入部署管理菜单，验证 Token 续期、审批、灰度、审计等关键路径。
- **持续集成**：PR 必须通过 `lint`、`test:run`、`build`；发布前执行 `npm run test:e2e`。

## 六、协同与依赖
- **后端/BFF 团队**：提供 `/api/releases`、`/api/deployments`、`/api/policies`、`/api/audits` 等接口；对 Token 续期、Nonce 校验进行审计。
- **主应用团队**：负责侧边栏导航、菜单权限、消息中心、Token Bridge 兼容性；提供 i18n 词条与 Design Token。
- **DevOps 团队**：配置 Argo CD Module Federation 构建流水线，确保 `deploy-platform` 远程模块可被 Host 加载；准备预生产环境联调。
- **安全合规**：在 Token 签发、审计材料、日志中校验隐私与合规要求。

## 七、风险与缓解
- **Token 失效或桥接异常**：构建详细的错误提示与重试机制，BFF 记录审计；并在 Host 侧写入监控。
- **多团队协作排期冲突**：建立每周同步会议，使用看板跟踪任务，提前通报接口变更。
- **模块联邦版本漂移**：锁定共享依赖版本，配置 Vite Federation `shared` 策略，增加契约测试。
- **性能退化**：按需加载组件、使用骨架屏、监控初始包大小，目标 < 300KB gzip。
- **国际化欠缺**：同步主应用 i18n 词条表，每个新组件确保 `zh-CN` / `en` 文案就绪。
