# AI 面板设计梳理

> 依据用户提供的 VS Code 插件截图提炼

## 1. 总览
- 面板用于驱动“AI 助手”工作流，当前会话标题显示为 `TRAe`。
- 界面采用深色主题，左侧为消息流，底部为输入与模型选择区。
- 面板支持同时展示文件引用、状态标签和系统通知，帮助用户对上下文和任务状态保持清晰认知。

## 2. 信息架构与布局
### 2.1 顶部区域
- 左侧展示会话名称（截图中文本：`TRAe`）。
- 右侧存在一组工具按钮（截图中为模糊图标，推测包含设置 / 历史等功能；需要后续确认具体含义）。

### 2.2 消息流区域
- 按时间顺序罗列 AI 与系统消息。
- 每条消息可包含以下元素：
  - **文件引用标签**：形如 `∞ src\main\resources\static\js\drawer.js`，使用图标 + 相对路径，点击后预计可跳转至对应文件。
  - **正文文本**：示例包括“现在让我检查服务器信息容器的样式，确保它正确布局。”等操作指令。
  - **状态徽标**：如 `Review`，用于标识当前消息对应任务的状态或需要执行的下一步。
  - **系统通知消息**：例如“模型参数改变成功”，用于反馈配置变更结果。
- 消息在视觉上分隔明确，正文左对齐，标签与徽标颜色对比明显，帮助用户快速识别上下文。

### 2.3 底部输入与控制区
- **模型选择器**：可下拉选择不同模型；截图中的选项包括：
  1. Doubao-Seed-1.6
  2. Kimi-K2-0905（当前选中项，带有勾选标记）
  3. Qwen-3-Coder

  5. GLM-4.5
  6. DeepSeek-V3.1
- **模型切换反馈**：选定模型后，消息流中出现“模型参数改变成功”系统消息，提示变更已生效。
- **输入框**：位于模型选择器下方，当前光标位置显示 `"^"` 字样，推测支持快捷指令或历史命令（需确认；建议在设计文档中保留备注）。
- **发送入口**：截图右下未完全展示按钮形态，但推断存在发送按钮或快捷键；后续需补充明确交互。

## 3. 关键交互
- **文件引用点击**：在消息中点击文件标签可能会在编辑器中打开对应文件，保持调试与改动的一致性。
- **状态徽标**：`Review` 徽标暗示消息关联的操作需要人工确认，可能与代码评审或任务检查流程联动。
- **模型切换**：用户打开下拉菜单，选择不同模型后立即收到系统反馈消息，确保模型上下文明确；该操作不会刷新历史消息。
- **连续指令执行**：截图中同一会话包含多条按步骤推进的指令（逐项检查样式、HTML 结构等），说明面板支持多轮对话与任务分解。

## 4. 文案与语言风格
- 主要语气为“现在让我…，确保…”等第一人称指令式，强调即时行动。
- 系统提示使用简短陈述（例如“模型参数改变成功”）。
- 文件标签和状态徽标均保持简洁英文或符号表示，便于识别。

## 5. 设计待确认点
- 顶部工具按钮的具体功能与可见性状态。
- 模型选择器是否支持搜索、收藏或动态加载模型列表。
- 输入框 `"^"` 的含义（快捷键提示 / 历史命令标识 / 其他功能）。
- 发送按钮的视觉样式与快捷键说明是否需要在界面中呈现。

## 6. 建议与补充
- 在设计稿或实现中，为模型切换加入 hover / keyboard focus 态，提升可访问性。
- 对状态徽标统一颜色体系（如 Review、Fix、Info 等），并在文档中说明用途。
- 若模型列表较长，考虑新增搜索或类别分组，以保障可扩展性。
- 单条消息若关联多个文件，建议支持多标签展示并与正文之间保持间距。
