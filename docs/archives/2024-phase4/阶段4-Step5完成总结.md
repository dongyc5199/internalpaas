### 前端API迁移

#### 1. 单服务器查询
```javascript
// 旧方式 (废弃但仍可用)
GET /monitoring/history/api/server/1/data?from=xxx&to=xxx

// 新方式 (推荐,性能更优)

```

#### 2. 批量服务器查询
```javascript
// 旧方式 (废弃但仍可用)
POST /monitoring/history/api/servers/compare
Body: { serverIds: [1,2,3], from, to }

// 新方式 (推荐,并发查询)
POST /monitoring/api/servers/hub/batch-query
Body: { serverIds: [1,2,3], from, to, step, fields }
```

#### 3. 实时数据查询
```javascript
// 旧方式 (废弃但仍可用)
GET /monitoring/history/api/server/1/realtime

// 新方式 (推荐,更灵活)
GET /monitoring/api/server/1/hub/query?from={now-5m}&to={now}&step=60
```

### 响应格式变化

**旧格式** (ServerMetrics模型):
```json
{
  "serverId": 1,
  "timestamp": 1697500800,
  "cpu": { "usage": 45.5, "cores": 8 }
}
```

**新格式** (Hub原始响应):
```json
{
  "server_id": 1,
  "metrics": [{
    "timestamp": 1697500800,
    "cpu_usage": 45.5
  }]
}
```

**迁移建议**:
- ✅ 前端调整字段映射(camelCase → snake_case)
- ✅ 新端点性能更优,建议优先使用
- ✅ 旧端点仍可用,无需立即迁移
- ✅ 可并行使用,渐进式迁移
