# Phase 6 手动测试快速指南

## 前提条件

1. **后端服务运行中**：
   ```bash
   ./mvnw.cmd spring-boot:run
   ```
   等待看到 "Started InternalpaasApplication"

2. **浏览器打开应用**：
   ```
   http://localhost:8080
   ```

3. **登录系统**：使用您的开发账户登录

## 测试 T069：验证5分钟缓存策略

### 步骤一：观察初始加载

1. 打开 **发布管理** 页面（Releases）
2. 按 `F12` 打开浏览器开发工具
3. 切换到 **Network** 标签
4. 点击页面左下角的 **React Query 图标**（花朵图标）打开 DevTools

### 步骤二：验证缓存命中

1. **观察初始请求**：
   - Network 标签中应该看到 `/api/releases` 请求
   - React Query DevTools 显示 `['releases', ...]` 查询状态为 `fetching` → `fresh`

2. **测试缓存**：
   - 点击导航栏切换到 **概览** 页面
   - 立即切换回 **发布管理**
   - ✅ **预期结果**：Network 中**没有**新的 `/api/releases` 请求
   - ✅ **预期结果**：React Query DevTools 中查询仍为 `fresh` 状态

3. **测试不同筛选条件**：
   - 使用页面上的筛选下拉框（状态、环境）
   - 每次更改筛选条件应触发新请求
   - DevTools 中会出现不同查询键的多个查询实例

### 步骤三：验证 staleTime（5分钟）

⏱️ **需要等待时间**：建议在第一次测试后继续测试 T070，5分钟后回来验证

1. **记录时间**：在 DevTools 的查询详情中查看 **Last Updated** 时间
2. **等待 5 分钟**
3. **重新访问页面**：
   - 切换到其他页面再切回 **发布管理**
   - ✅ **预期结果**：查询状态变为 `stale`
   - ✅ **预期结果**：触发后台刷新（Network 中看到新请求）
   - ✅ **预期结果**：页面继续显示缓存数据，刷新完成后更新

### 验证清单

- [ ] 初始加载显示数据
- [ ] 5分钟内切换页面无新请求（缓存命中）
- [ ] 不同筛选条件触发新请求（查询键隔离）
- [ ] 5分钟后数据标记为 stale
- [ ] stale 数据仍可见，后台自动刷新

## 测试 T070：验证乐观更新

### 步骤一：观察正常的乐观更新

1. 打开 **策略配置** 页面（Settings → Policies）
2. 打开 React Query DevTools
3. 打开浏览器 DevTools 的 **Network** 标签

### 步骤二：测试状态切换（成功场景）

1. **准备观察**：
   - 找到一个状态为 "激活" 的策略
   - 在 React Query DevTools 中点击 `['policies', ...]` 查询
   - 观察 **Data** 标签中该策略的 `status` 字段

2. **执行操作**：
   - 点击该策略的 **停用** 按钮
   - 👀 **立即观察**：
     - ✅ 表格中该行的状态徽章**立即变为"停用"**（无需等待）
     - ✅ DevTools 的 Data 标签中 `status` 字段**立即更新为** `'inactive'`
     - ✅ **Last Updated** 时间戳更新

3. **等待服务器响应**：
   - 几百毫秒后，Network 标签显示请求完成
   - ✅ DevTools 再次更新 **Last Updated**（服务器确认）
   - ✅ 表格状态保持不变（乐观更新被服务器确认）

### 步骤三：测试编辑模态框

1. 点击任意策略的 **编辑** 按钮
2. 在模态框中更改状态
3. 阅读提示文字：
   > 💡 提示: 点击"保存"后，表格会立即更新（乐观更新）。如果保存失败，将自动回滚到原始状态。

4. 点击 **保存**
5. ✅ **预期结果**：
   - 模态框关闭
   - 表格**立即更新**
   - 后台请求完成后数据保持一致

### 步骤四：测试失败回滚（错误场景）

⚠️ **需要模拟错误环境**

**方法1：关闭后端服务**
```bash
# 在运行 Spring Boot 的终端按 Ctrl+C 停止服务
```

**方法2：使用浏览器离线模式**
1. 在浏览器 DevTools 的 **Network** 标签中
2. 勾选 **Offline** 复选框（模拟网络断开）

**执行测试**：
1. 点击策略的 **停用** 或 **激活** 按钮
2. 👀 **观察完整流程**：
   - ✅ 表格**立即更新**（乐观更新）
   - ✅ DevTools 数据**立即更新**
   - ⏱️ 等待几秒（请求超时）
   - ✅ 弹出错误提示：`更新失败: ...`
   - ✅ 表格**自动恢复**到原始状态（回滚）
   - ✅ DevTools 数据**回滚**到修改前的值

3. **恢复环境**：
   - 如果关闭了后端，重新启动：`./mvnw.cmd spring-boot:run`
   - 如果使用了 Offline 模式，取消勾选 **Offline**

## 调试技巧

### 使用慢速网络观察乐观更新

1. 在浏览器 DevTools **Network** 标签
2. 下拉框选择 **Slow 3G** 或 **Fast 3G**
3. 执行策略状态切换
4. 更清晰地看到：
   - 立即的 UI 更新（乐观）
   - 延迟的服务器响应
   - 两次更新的时间差

### 查看 React Query 内部状态

在 React Query DevTools 中：
1. 点击具体的查询（如 `['policies', undefined, 1, 20]`）
2. 查看详细信息：
   - **Data**: 当前缓存的数据
   - **Query Key**: 查询键（用于缓存隔离）
   - **Last Updated**: 最后更新时间戳
   - **Data Updated At**: 数据更新的精确时间
   - **Observers**: 订阅此查询的组件数量

### 手动操作查询

DevTools 提供的操作按钮：
- **Refetch**: 强制重新获取（忽略缓存）
- **Invalidate**: 标记为失效并重新获取
- **Reset**: 重置查询状态
- **Remove**: 从缓存中移除

## 预期性能指标

### 缓存命中场景
- **首次加载**: ~200-500ms（含网络请求）
- **缓存加载**: ~10-50ms（纯内存读取，快 10-50 倍）

### 乐观更新场景
- **UI 响应**: <16ms（1帧，即时）
- **网络请求**: 200-1000ms（后台进行）
- **用户感知延迟**: 0ms（UI 已更新）

### 回滚场景
- **错误检测**: ~5000ms（请求超时）
- **回滚执行**: <16ms（即时）
- **错误提示**: 立即显示

## 常见问题

### Q: DevTools 图标在哪里？

**A**: 页面左下角，红色花朵图标。如果看不到：
1. 确认浏览器控制台无错误
2. 刷新页面（Ctrl+F5 强制刷新）
3. 检查是否在开发环境

### Q: 乐观更新没有生效

**A**: 检查：
1. 是否使用了启用乐观更新的 hook（`enableOptimisticUpdate: true`）
2. 浏览器控制台是否有 JavaScript 错误
3. React Query DevTools 中查询是否正确更新

### Q: 缓存一直刷新，无法命中

**A**: 可能原因：
1. 查询键不一致（检查 DevTools 中的 Query Key）
2. `staleTime` 设置为 0（检查 `queryClient.ts` 配置）
3. 组件重新挂载导致重新订阅

### Q: 测试回滚时没有看到错误

**A**: 确保：
1. 后端确实停止或网络确实断开
2. 等待足够时间（默认超时 5 秒）
3. 检查浏览器控制台的错误消息
