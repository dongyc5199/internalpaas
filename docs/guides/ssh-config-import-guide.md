## 功能概述

SSH配置导入功能允许管理员从SSH配置文件（通常是 `~/.ssh/config`）快速批量导入服务器到Dev Debug Platform。该功能支持：

- ✅ **一键扫描本地配置**: 自动读取 `~/.ssh/config` 文件
- ✅ **文件上传**: 支持拖拽上传或选择配置文件
- ✅ **自定义路径**: 解析任意路径的SSH配置文件
- ✅ **智能解析**: 自动提取主机名、端口、用户名、密钥等信息
- ✅ **去重检测**: 导入前自动检测重复服务器
- ✅ **批量验证**: 验证必填字段，标记缺失信息
- ✅ **可视化预览**: 表格形式预览所有服务器，支持行内编辑
- ✅ **批量导入**: 一次导入多台服务器

## 前置条件

### 用户权限要求
- 必须具有 **管理员（ADMIN）** 或 **超级管理员（SUPER_ADMIN）** 权限
- 普通用户（USER）无法访问SSH配置导入功能

### SSH配置文件要求
- 文件格式: 纯文本文件（推荐 `.config` 或 `.txt` 扩展名）
- 文件大小: ≤ 1 MB
- 编码格式: UTF-8
- 内容格式: 标准OpenSSH配置格式

### 必填字段
每个导入的服务器必须包含以下信息：
- **名称** (Name): 服务器名称，不可重复
- **主机名** (Hostname): IP地址或域名
- **SSH用户名** (User): SSH登录用户名
- **认证凭证**: SSH密码 或 SSH私钥路径（至少提供一项）

1. 选择 **"扫描本地配置"** 选项卡

#### 方式2: 上传配置文件 📤

**适用场景**: 从其他位置或备份文件导入

1. 选择 **"上传配置文件"** 选项卡
2. 点击上传区域或 **拖拽文件** 到虚线区域
3. 选择配置文件（支持 `.config`, `.txt` 等文本文件）

- 松开鼠标，文件自动上传
- 上传中会显示进度条

**文件限制**:
- 最大文件大小: 1 MB
- 允许的MIME类型: `text/plain`, `application/octet-stream`
- 如果超出限制，系统会显示错误提示

---

#### 方式3: 输入自定义路径 🔍

**适用场景**: 解析非默认路径的配置文件

1. 选择 **"输入自定义路径"** 选项卡
2. 在输入框中输入配置文件路径

3. 点击 **"解析配置"** 按钮

- 支持 `~/` 快捷方式（展开为用户主目录）
- 支持 `$HOME/` 环境变量
- 支持绝对路径
- 支持相对路径

## SSH配置文件格式

### 标准格式

SSH配置文件遵循OpenSSH配置格式，每个Host块定义一台服务器：

```ssh
# 注释行（以#开头）

Host server1
    HostName 192.168.1.100
    Port 22
    User root
    IdentityFile ~/.ssh/id_rsa

Host server2
    HostName example.com
    User admin
    Port 2222
```

### 支持的配置项

| 配置项 | 说明 | 是否必填 | 示例 |
|--------|------|---------|------|
| Host | 服务器别名（用作默认名称） | ✅ 必填 | `Host my-server` |
| HostName | 主机名或IP地址 | ✅ 必填 | `HostName 192.168.1.100` |
| Port | SSH端口 | 可选，默认22 | `Port 2222` |
| User | SSH用户名 | ✅ 必填 | `User root` |
| IdentityFile | SSH私钥路径 | 可选 | `IdentityFile ~/.ssh/id_rsa` |

### 不支持的配置项

以下配置项会被忽略或产生警告：

- **ProxyJump**: 跳板机配置（会产生警告）
- **Include**: 包含其他配置文件（会产生警告）
- **通配符Host**: 如 `Host *` 或 `Host *.example.com`（会被跳过）

### 路径展开

系统自动展开以下路径格式：

- `~/` → 用户主目录
  - Windows: `C:\Users\{用户名}\`
  - Linux/Mac: `/home/{用户名}/`
- `$HOME/` → 用户主目录
- 绝对路径保持不变

**示例**:
```ssh
Host server1
    IdentityFile ~/.ssh/id_rsa
    # 展开为: C:\Users\admin\.ssh\id_rsa (Windows)
    #        /home/admin/.ssh/id_rsa (Linux)
```

### 完整示例

```ssh
# Dev Debug Platform - SSH配置示例
# 创建日期: 2025-10-19

# 开发服务器1
Host dev-server-1
    HostName 192.168.1.100
    Port 22
    User root
    IdentityFile ~/.ssh/dev_key

# 开发服务器2（使用密码认证）
Host dev-server-2
    HostName 192.168.1.101
    Port 2222
    User admin

# 生产服务器
Host prod-server
    HostName prod.example.com
    Port 22
    User deploy
    IdentityFile ~/.ssh/prod_key
```

**导入结果**:
- dev-server-1: ✅ 就绪（有私钥路径）
- dev-server-2: ❌ 缺失字段（需手动添加密码）
- prod-server: ✅ 就绪（有私钥路径）

## 常见问题

### Q1: 为什么我看不到"SSH配置导入"按钮？

**A**: 该功能仅对管理员开放。请确认您的账号具有 **ADMIN** 或 **SUPER_ADMIN** 权限。

---

### Q2: 扫描本地配置提示"文件不存在"？

**A**: 可能的原因：
1. 系统默认路径下没有 `config` 文件
2. 文件路径不正确

**解决方法**:
- 使用 **"输入自定义路径"** 方式，手动指定配置文件路径
- 或使用 **"上传配置文件"** 方式上传配置文件

---

### Q3: 上传文件提示"文件大小超过限制"？

**A**: SSH配置文件最大限制为 **1 MB**。

**解决方法**:
- 拆分大配置文件为多个小文件
- 删除配置文件中的注释和空行
- 只保留需要导入的Host块

---

### Q4: 为什么有些Host没有被解析？

**A**: 以下Host会被自动跳过：
- 通配符Host（如 `Host *`, `Host *.example.com`）
- 全局配置块（`Host *`）
- 缺少HostName的Host

---

### Q5: 导入后服务器状态显示"离线"？

**A**: 导入成功并不代表SSH连接成功。系统会在后台异步测试SSH连接，可能需要数秒。

**解决方法**:
1. 等待数秒后刷新服务器列表
2. 手动点击服务器的 **"测试连接"** 按钮
3. 检查SSH凭证（密码/私钥）是否正确

---

### Q6: 导入失败提示"服务器已存在"？

**A**: 数据库中已有相同 **hostname + sshPort** 的服务器。

**解决方法**:
- 修改重复服务器的名称
- 或删除旧服务器后重新导入

---

### Q7: 支持导入多少台服务器？

**A**: 理论上无限制，但建议：
- **单次导入**: ≤ 100 台（性能最佳）
- **配置文件**: ≤ 500 个Host块（1MB限制内）

**性能参考** (Day 10 E2E测试结果):
- 100个Host解析: < 5秒
- 50台服务器导入: < 30秒

---

### Q8: 私钥路径导入后无法连接？

**A**: 请确认：
1. 私钥文件在服务器端存在（系统不会上传私钥）
2. 私钥路径使用绝对路径或 `~/` 格式
3. 私钥文件权限正确（Linux: 600）

**建议**:
- 优先使用密码认证
- 或在服务器管理页面手动配置私钥

---

### Q9: 可以导入ProxyJump配置吗？

**A**: 目前不支持。ProxyJump配置会产生警告，但不会阻止其他字段的解析。

**解决方法**:
- 忽略ProxyJump警告
- 导入后手动配置跳板机

---

### Q10: 导入的服务器类型都是"DEVELOPMENT"？

**A**: 这是默认值。可以在步骤2预览阶段修改：

1. 点击服务器的 **"编辑"** 按钮
2. 在 **"服务器类型"** 下拉框中选择：
   - DEVELOPMENT（开发）
   - TESTING（测试）
   - STAGING（预发布）
   - PRODUCTION（生产）
3. 点击 **"保存"**

---

## 故障排除

### 问题1: 上传文件后无响应

**症状**: 点击上传按钮或拖拽文件后，没有任何反应

**可能原因**:
1. 文件格式不正确
2. 文件大小超过1MB
3. 浏览器不支持文件上传API

**排查步骤**:
1. 检查浏览器控制台是否有错误信息（F12 → Console）
2. 确认文件大小 ≤ 1MB
3. 尝试使用其他浏览器（推荐Chrome/Edge）
4. 清除浏览器缓存后重试

---

### 问题2: 解析结果为空或只有少数服务器

**症状**: 明明配置文件有多个Host，但解析结果只有少数或为空

**可能原因**:
1. 配置文件格式错误
2. Host块缺少HostName字段
3. 大量通配符Host被跳过

**排查步骤**:
1. 检查配置文件是否符合OpenSSH格式
2. 确认每个Host块都有 `HostName` 行
3. 查看解析警告信息，确认哪些Host被跳过
4. 手动验证配置文件语法：
   ```bash
   ssh -G <host-alias>
   ```

---

### 问题3: 批量导入时部分失败

**症状**: 导入结果显示"部分成功"，有失败详情

**可能原因**:
1. 重复服务器（hostname+port已存在）
2. 必填字段缺失
3. 数据库约束冲突

**排查步骤**:
1. 查看失败详情表格，确认具体失败原因
2. 对于重复服务器：
   - 检查现有服务器列表
   - 删除旧服务器或修改新服务器的hostname/port
3. 对于字段缺失：
   - 返回步骤2，点击"编辑"补充信息
4. 对于数据库错误：
   - 联系管理员查看服务器日志
   - 路径: `logs/application.log`

---

### 问题4: 导入成功但连接失败

**症状**: 导入显示成功，但服务器状态为"离线"或"连接失败"

**可能原因**:
1. SSH凭证不正确（密码错误或私钥路径错误）
2. 服务器端SSH服务未启动
3. 网络不通或防火墙阻止

**排查步骤**:
1. 在服务器管理页面点击 **"测试连接"** 查看详细错误
2. 检查SSH密码是否正确（如果使用密码认证）
3. 检查私钥路径是否存在（如果使用私钥认证）
4. 手动SSH测试：
   ```bash
   ssh -p <port> <user>@<hostname>
   ```
5. 检查服务器端SSH服务：
   ```bash
   systemctl status sshd
   ```

---

### 问题5: 私钥路径展开不正确

**症状**: 私钥路径显示为 `~/...` 而不是绝对路径

**说明**: 这是正常现象。系统会在运行时动态展开 `~/`。

**验证方法**:
1. 在服务器详情页面查看实际使用的路径
2. 或查看后台日志确认路径展开结果

---

### 问题6: 性能问题（导入速度慢）

**症状**: 导入50+服务器时耗时很长

**可能原因**:
1. 异步连接测试占用资源
2. 数据库性能瓶颈

**优化建议**:
1. 分批导入（每批20-30台）
2. 导入后等待连接测试完成再继续
3. 如果数据库为H2，考虑升级到PostgreSQL/MySQL

---

### 问题7: 导入向导卡在某个步骤

**症状**: 点击"下一步"或"开始导入"无响应

**排查步骤**:
1. 检查浏览器控制台错误（F12 → Console）
2. 检查网络请求状态（F12 → Network）
3. 确认后端服务正常运行
4. 查看服务器日志:
   ```bash
   tail -f logs/application.log
   ```
5. 刷新页面重试

---

### 问题8: 中文乱码

**症状**: 导入结果或错误信息显示乱码

**可能原因**:
1. 配置文件编码不是UTF-8
2. 浏览器编码设置问题

**解决方法**:
1. 确保配置文件保存为UTF-8编码
2. 使用记事本/VS Code打开配置文件，检查编码
3. 设置浏览器编码为UTF-8
