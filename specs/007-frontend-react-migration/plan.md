# Implementation Plan: Frontend React Migration

**Branch**: `007-frontend-react-migration` | **Date**: 2025-01-04 | **Spec**: [spec.md](./spec.md)

## Summary

Migrate Dev Debug Platform's hybrid frontend architecture (44 Thymeleaf templates + 9,154 lines vanilla JavaScript) to a unified React SPA. Technical approach uses Vite + React 18 + TypeScript with Zustand state management, React Query for data fetching, and ECharts for visualization. Migration follows 6 phases over 20 weeks, starting with foundational infrastructure (React shell, auth, component library), then progressively migrating modules by complexity (admin dashboard → SSH terminal → monitoring → forms/config).

**Key Benefits**: 30% faster Time to Interactive, 70% unit test coverage, modern development experience with HMR, type safety, and component reusability reducing feature development time by 50%.

**Structure Decision**:
- **Hybrid during migration**: Legacy Thymeleaf templates coexist with React SPA during 20-week migration period
- **Feature-based organization**: React code organized by business domain (admin, monitoring) rather than technical layer (components, services)
- **Co-location**: Related files (components, hooks, API, types) grouped together in feature folders
- **Lazy loading**: Each feature module lazy-loaded as separate chunk for optimal initial load time
- **Progressive cleanup**: Legacy Thymeleaf templates removed incrementally as React equivalents stabilize

**Rationale**:
- Feature-based structure reduces coupling, easier to understand and maintain
- Co-location makes finding related code fast (no jumping between folders)
- Matches existing backend module structure (controller/admin, controller/monitoring)
- Enables parallel development (different developers work on different features without conflicts)
- Lazy loading ensures users only download code for features they access

## Phase 0: Research & Technology Decisions ✅ COMPLETE

**Status**: Complete - See [research.md](./research.md)

**Key Decisions Made**:
1. **State Management**: Zustand (lightweight, simple API, great TypeScript support)
2. **Routing**: React Router v6 (de facto standard, nested routes, type-safe params)
3. **Data Fetching**: TanStack Query + Axios (caching, optimistic updates, interceptors)
4. **Charts**: Apache ECharts (best performance, rich features, already in project)
5. **Forms**: React Hook Form + Zod (performant, type-safe validation)
6. **WebSocket**: Custom hooks + STOMP.js (backend compatibility)
7. **Styling**: CSS Modules (zero-runtime, scoped, works with existing --shell-* variables)
8. **Build Tool**: Vite (fast HMR, excellent DX, Rollup production builds)
9. **i18n**: react-i18next (most popular, dynamic switching)
10. **Testing**: Vitest + React Testing Library + MSW (fast, behavior-focused, network mocking)

**Alternatives Evaluated**: Redux, MobX, Jotai (state); SWR, RTK Query (data); Recharts, Chart.js (charts); Formik (forms); Webpack (build); FormatJS (i18n); Jest (testing)

**Architectural Patterns Established**:
- Feature-based folder structure
- Custom hook pattern for API calls
- Protected route pattern for authentication
- Error boundary pattern at route level
- Code splitting strategy (route + component level)

**Deliverables Generated**:

### 1. Data Model ([data-model.md](./data-model.md))
- **Core Entities**: User, Server, Application, SSH Session, Server Group, Monitoring Data
- **Frontend Entities**: UI State, WebSocket Connection State
- **Validation Rules**: Zod schemas for Server, Application, User forms
- **State Transitions**: Server status, Application status, SSH session status state machines
- **State Management Strategy**: Zustand for global state, React Query cache for server data, component-local for UI state

### 2. API Contracts

#### REST API ([contracts/api-specification.yaml](./contracts/api-specification.yaml))
- **OpenAPI 3.0.3 Specification**: 50+ endpoints covering authentication, servers, applications, users, monitoring, SSH, configuration
- **Authentication**: Session-based (JSESSIONID cookie)
- **Endpoints Organized by Tag**: Authentication, Servers, Applications, Users, Monitoring, SSH, Config
- **Schemas Defined**: User, Server, Application, SSHSession, ServerMetrics, ApplicationConfig, AlertThreshold
- **Error Responses**: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found

**Key Endpoints**:
- `POST /api/auth/login` - User login
- `GET /api/servers` - List all servers
- `POST /api/servers` - Create server (admin only)
- `GET /api/servers/{serverId}/metrics` - Server metrics (historical + current)
- `POST /api/applications` - Upload JAR application
- `POST /api/applications/{appId}/start` - Start application
- `GET /api/ssh/sessions` - List SSH sessions
- `POST /api/ssh/sessions` - Create new SSH session

#### WebSocket Specification ([contracts/websocket-specification.md](./contracts/websocket-specification.md))
- **Protocol**: STOMP over WebSocket
- **Endpoint**: `ws://localhost:8080/ws`
- **Authentication**: Session cookie (JSESSIONID)

**Topics**:
- `/topic/server-status/{serverId}` - Real-time server metrics (5s intervals)
- `/topic/application-status/{appId}` - Application lifecycle events
- `/app/ssh/{sessionId}/input` (send) + `/topic/ssh/{sessionId}/output` (receive) - SSH terminal I/O
- `/topic/application-logs/{appId}` - Real-time log streaming
- `/topic/servers` - Global server list updates (event-driven)
- `/user/queue/notifications` - Personal user notifications

### 3. Developer Quickstart ([quickstart.md](./quickstart.md))
- **Prerequisites**: Node.js 18+, Java 17+, npm 9+
- **Setup Instructions**: Clone, install dependencies, start dev servers
- **Development Workflow**: HMR, API proxy, debugging
- **Common Tasks**: Create components, add API hooks, WebSocket integration, run tests
- **Troubleshooting**: Port conflicts, dependency issues, TypeScript errors, WebSocket failures
- **Code Style Guide**: Naming conventions, file structure, component patterns
