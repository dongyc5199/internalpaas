# Feature Specification: AI助手输入框UI优化

**Feature Branch**: `002-refine-input-ui`
**Created**: 2025-10-22
**Status**: Draft
**Input**: User description: "参考截图完善优化输入框"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看和管理上下文标签 (Priority: P1)

用户在使用AI助手时，需要清晰地看到哪些会话上下文已经被添加到当前对话中，并能够方便地管理这些上下文（添加或移除）。

**Why this priority**: 这是核心用户体验改进，直接影响用户对AI助手上下文功能的理解和使用效率。清晰的视觉层次可以让用户立即知道哪些信息会被发送给AI。

**Independent Test**: 打开AI助手面板，添加SSH会话上下文（通过#触发），验证上下文标签是否在独立的标签区域显示，带有明显的视觉区分（背景色、图标），并且可以通过点击关闭按钮移除。

**Acceptance Scenarios**:

1. **Given** 用户打开AI助手面板，**When** 用户输入`#`并选择一个SSH会话，**Then** 在输入框上方显示一个蓝色背景的标签，包含会话图标和名称
2. **Given** 用户已添加上下文标签，**When** 用户点击标签上的关闭按钮（×或+），**Then** 标签从界面上移除，该会话上下文不再包含在后续消息中
3. **Given** 用户添加了多个上下文标签，**When** 查看标签区域，**Then** 所有标签在独立的标签栏中横向排列，标签栏与输入区域有明显的视觉分隔

---

### User Story 2 - 使用增强的输入提示 (Priority: P1)

用户首次使用AI助手时，需要了解可以使用哪些特殊功能（如添加上下文、@提及、/命令），占位符文本应该清晰地提示这些功能。

**Why this priority**: 良好的用户引导可以大幅提升功能发现率和使用率，减少用户学习成本。

**Independent Test**: 打开AI助手面板，查看空输入框，验证占位符文本是否显示"添加上下文(#)、扩展(@)、命令(/)"或类似的多功能提示。

**Acceptance Scenarios**:

1. **Given** 用户首次打开AI助手，**When** 查看输入框，**Then** 占位符文本清晰显示多种触发器（#、@、/）及其功能说明
2. **Given** 用户开始输入文本，**When** 输入框获得焦点，**Then** 占位符文本消失，输入框显示用户输入的内容
3. **Given** 用户清空输入框，**When** 输入框失去焦点，**Then** 占位符文本重新显示

---

### User Story 3 - 访问快捷设置和更多选项 (Priority: P2)

用户需要快速访问AI助手的设置（如流式输出开关、速度调整）和更多功能选项，而不需要打开完整的设置面板。

**Why this priority**: 提供便捷的设置访问可以提升用户满意度，但不影响核心对话功能。

**Independent Test**: 在输入框底部工具栏，点击设置图标（⚙️）或更多菜单图标（⋮），验证是否打开对应的选项面板。

**Acceptance Scenarios**:

1. **Given** 用户在底部工具栏看到设置图标（⚙️），**When** 点击该图标，**Then** 打开设置抽屉或弹出菜单，显示流式输出开关、速度选择等选项
2. **Given** 用户在底部工具栏看到更多选项图标（⋮），**When** 点击该图标，**Then** 显示额外的功能选项（如清空对话、导出对话等）
3. **Given** 用户打开了设置面板，**When** 点击面板外部或按ESC键，**Then** 设置面板关闭

---

### User Story 4 - 使用优化的下拉选择器 (Priority: P2)

用户需要在不同的AI模式（Ask/Agent）和模型（Kimi K2等）之间切换，下拉选择器应该清晰显示当前选择，并带有下拉箭头指示器。

**Why this priority**: 改进选择器的视觉设计可以提升专业感和易用性，但不影响核心功能。

**Independent Test**: 查看底部工具栏的模式和模型选择器，验证是否有下拉箭头图标，点击时是否正确展开选项列表。

**Acceptance Scenarios**:

1. **Given** 用户查看底部工具栏，**When** 看到模式选择器（Agent ▼），**Then** 选择器显示当前模式名称和下拉箭头图标
2. **Given** 用户点击模式选择器，**When** 下拉列表展开，**Then** 显示所有可用模式（Ask、Agent等），禁用的选项显示为灰色
3. **Given** 用户选择了新的模式或模型，**When** 下拉列表关闭，**Then** 选择器显示新选择的名称

---

### User Story 5 - 使用改进的发送按钮 (Priority: P3)

用户完成消息输入后，需要点击发送按钮或使用快捷键发送消息，发送按钮应该有清晰的视觉标识（三角形播放图标）。

**Why this priority**: 这是视觉美化，改进用户界面的一致性和现代感，但不改变功能。

**Independent Test**: 查看底部工具栏右侧，验证发送按钮是否使用三角形图标（▶️）而非文字"发送"。

**Acceptance Scenarios**:

1. **Given** 用户输入了消息文本，**When** 查看发送按钮，**Then** 按钮显示三角形图标（▶️），悬停时有高亮效果
2. **Given** 用户点击发送按钮，**When** 消息正在发送，**Then** 按钮变为禁用状态，可选显示加载动画
3. **Given** AI正在回复，**When** 查看发送按钮，**Then** 按钮保持禁用状态直到AI回复完成

---

### Edge Cases

- **当用户添加多个上下文标签时**：标签区域应该支持横向滚动或自动换行，确保所有标签都可见
- **当用户输入超长文本时**：输入框应该自动扩展高度（在设定的最大高度范围内），并显示滚动条
- **当网络连接中断时**：发送按钮应该显示错误状态，提示用户检查网络连接
- **当用户尝试发送空消息时**：发送按钮应该保持禁用状态，避免发送空白内容
- **当上下文标签过多导致界面拥挤时**：系统应该显示标签数量指示器（如"已添加5个上下文"），并提供查看全部的方式

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在输入框上方提供独立的标签区域，用于显示已添加的SSH会话上下文
- **FR-002**: 每个上下文标签必须显示会话图标、会话名称，并提供关闭按钮
- **FR-003**: 上下文标签区域必须与输入区域有明显的视觉区分（通过背景色、边框或间距）
- **FR-004**: 输入框占位符必须提示多种功能触发器（#添加上下文、@扩展、/命令）
- **FR-005**: 底部工具栏必须包含设置按钮（⚙️图标）和更多选项按钮（⋮图标）
- **FR-006**: 模式选择器和模型选择器必须显示下拉箭头图标（▼），提示用户可以展开选项
- **FR-007**: 发送按钮必须使用三角形图标（▶️）而非文字标签
- **FR-008**: 所有图标按钮必须有悬停效果（背景高亮或阴影）
- **FR-009**: 输入框必须支持自动高度调整，在用户输入多行文本时扩展（限定最大高度）
- **FR-010**: 当用户点击上下文标签的关闭按钮时，系统必须移除该标签并从上下文列表中删除对应的会话

### Key Entities

- **上下文标签 (Context Chip)**: 代表一个已选择的SSH会话上下文，包含会话ID、显示名称、服务器地址、关闭按钮状态
- **输入区域 (Input Area)**: 用户输入消息的区域，包含输入框、占位符文本、当前输入值、焦点状态
- **工具栏 (Toolbar)**: 位于输入框底部，包含模式选择器、模型选择器、设置按钮、发送按钮、更多选项按钮
- **选择器 (Selector)**: 下拉选择组件，包含当前选择值、可用选项列表、展开/折叠状态

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在3秒内识别已添加的上下文标签并理解其含义（通过颜色、图标、位置区分）
- **SC-002**: 用户能够在2次点击内完成添加或移除上下文标签的操作
- **SC-003**: 90%的新用户能够通过占位符文本发现#、@、/三种功能触发器
- **SC-004**: 用户能够在1次点击内访问设置或更多选项菜单
- **SC-005**: 界面响应时间保持在50毫秒以内，用户点击按钮后立即看到视觉反馈（悬停效果、禁用状态等）
- **SC-006**: 输入框支持最多500个字符的输入而不出现性能下降或UI卡顿
- **SC-007**: 所有图标按钮（设置、更多、发送）的点击成功率达到95%以上（按钮尺寸足够大，易于点击）

## Assumptions

1. **现有功能保留**: 假设当前AI助手的所有功能（流式输出、键盘快捷键、#上下文选择等）将被保留，此次优化仅针对UI层
2. **设计参考**: 假设用户提供的截图代表理想的UI设计，本规范中的视觉要求基于该截图分析
3. **图标来源**: 假设使用Unicode字符或内联SVG实现图标，不依赖外部图标库
4. **颜色方案**: 假设遵循当前深色主题的配色方案（深蓝灰背景、浅色文字、蓝色强调色）
5. **浏览器兼容性**: 假设目标浏览器支持现代CSS特性（Flexbox、Grid、CSS变量、自定义滚动条等）
6. **响应式设计**: 假设界面需要在桌面端和移动端都有良好的显示效果，但移动端优先级较低

## Out of Scope

以下内容不在本次优化范围内：

1. **新增功能**: 不添加@扩展和/命令功能的实际实现，仅在占位符中提示（为未来功能预留）
2. **后端改动**: 不修改任何后端API或数据结构
3. **性能优化**: 不涉及JavaScript性能优化或代码重构，仅限UI/CSS改进
4. **国际化**: 不添加多语言支持，所有文本保持中文
5. **暗黑/明亮模式切换**: 仅优化当前的暗黑模式，不实现明亮模式
6. **语音输入功能**: 不实现语音输入按钮的实际功能（保留为占位符）
7. **历史记录功能**: 不改进或新增历史会话管理功能
